# 프로젝트 설정

## 도메인

`repo-bootstrap`은 Codex와 Claude에서 공통으로 쓰는 저장소 초기 세팅용 로컬 툴킷이다. 주요 산출물은 전역 AI 스킬 설치 스크립트, GitHub 이슈/PR 템플릿 설치 스크립트, AI 리뷰 지침, 그리고 각 스킬의 `SKILL.md` 원본이다.

## 운영 주체

- 이 저장소를 유지보수하는 개발자
- `curl | bash` 또는 clone 후 로컬 실행으로 초기 세팅을 설치하는 사용자
- GitHub PR에서 한국어 리뷰 지침을 기대하는 AI 리뷰 도구

## 첫 성공 시나리오

1. 사용자가 `install.sh`를 실행해 Codex/Claude 스킬과 선택적 Codex 플러그인을 설치한다.
2. 사용자가 `setup-github.sh`를 대상 저장소에서 실행해 이슈/PR 템플릿과 AI 리뷰 지침을 설치한다.
3. 사용자가 `uninstall.sh`를 실행해 repo-bootstrap이 관리한 글로벌 스킬을 제거한다.

## 품질 실패 비용이 큰 지점

- 전역 경로(`~/.codex`, `~/.claude`)를 잘못 수정하거나 삭제하는 경우
- `curl | bash` 기본 경로에서 외부 네트워크, npm 패키지, GitHub tarball을 예상보다 공격적으로 실행하는 경우
- 템플릿 설치가 대상 저장소의 기존 `AGENTS.md`나 `.gemini/styleguide.md`를 과하게 덮어쓰는 경우
- README의 설치/제거 정책과 실제 스크립트 옵션이 어긋나는 경우

## 보류한 구현 경계

- 실제 사용자 홈 디렉터리에서 `npx cc-plugin-codex install` 또는 `uninstall`을 실행하는 검증은 전역 설정 변경 위험 때문에 기본 자동 검증에서 제외한다.
- upstream 스킬 tarball 구조는 외부 저장소 변경에 따라 달라질 수 있으므로, 실패 시 원인 메시지를 보존하고 수동 재시도를 안내한다.

## 다음 재진입 기준

- 설치/제거 정책이나 전역 경로 처리 정책이 바뀌면 `하네스 Phase 1`과 `하네스 Phase 2`로 재진입한다.
- 역할 경계나 로컬 스킬 포인터가 어긋나면 `하네스 Phase 4`로 재진입한다.
- 로그, 최신 요약, 운영 감사 판정이 낡으면 `하네스 Phase 5`와 `하네스 Phase 6`으로 재진입한다.
