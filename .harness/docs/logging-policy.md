# 하네스 로그 정책

## 로그 목적

하네스 로그는 다음 실행 역할이 현재 상태를 추측하지 않도록 하는 Markdown 기록이다. 통계 수집이나 자동 append 스크립트가 아니라, 사람이 읽고 이어받을 수 있는 세션 저널과 최신 요약을 유지한다.

## 필수 로그 문서

- `.harness/logs/session-log.md`: 세션 단위 누적 기록
- `.harness/logs/latest-session-summary.md`: 다음 실행 판단에 필요한 최신 상태
- `.harness/logs/github-workflow-log.md`: GitHub Workflow Engine 보조 체크포인트

## 세션 시작 기록 항목

- 시각
- 세션 ID
- 시작 요청
- 진입점
- 계획 역할
- 예상 산출물

## 역할 완료 기록 항목

- 호출 역할
- 실행 결과 상태
- 입력 요약
- 출력 요약
- 변경 파일
- 다음 권장 역할
- 남은 위험
- 메모

## 최신 요약 기록 항목

- 세션 ID
- 시작/종료 시각
- 현재 하네스 Phase
- 최근 입력/출력
- 최근 변경 파일
- 다음 시작 역할
- 다음 하네스 재진입 Phase
- 다음 시작 전 우선 확인 입력 파일
- 남은 위험
- 학습 후보, 반복 신호, 승격 대상, 생성기 환류 후보

## 보류/실패 기록 기준

- 환경성 권한 문제, 승인 이력, 일회성 샌드박스 문제는 `session-log.md`에 남긴다.
- 다음 실행의 역할 선택이나 검증 기준에 직접 영향을 주는 위험만 `latest-session-summary.md`에 남긴다.
- 하네스 생명주기 단계는 `하네스 Phase N`으로 쓰고, 제품/로드맵 단계와 섞지 않는다.

## 완료 전 확인 기준

- 현재 세션 ID가 `session-log.md`와 `latest-session-summary.md`에 모두 있어야 한다.
- `latest-session-summary.md`에는 다음 시작 역할과 다음 하네스 재진입 Phase가 있어야 한다.
- 새로 확인한 저장소 사실이나 반복될 수 있는 판단이 있으면 학습 후보와 승격 대상 위치를 함께 남긴다.
